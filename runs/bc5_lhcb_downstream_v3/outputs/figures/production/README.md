# Production parameter-space figures — 13 TeV, LHCb downstream

Parent-particle production in the (theta, p) plane for the six species used as
long-lived-scalar parents in the BC5 LHCb-downstream analysis:

    production_Bplus.{png,pdf}   production_B0.{png,pdf}   production_Bs.{png,pdf}
    production_Kplus.{png,pdf}   production_K0L.{png,pdf}  production_Higgs.{png,pdf}
    production_all_particles.png   (2 x 3 grid of the same six panels)

Generated by `work/analysis/plot_production.py` (see the last section).

**v3.6 update (2026-10-25).**  The samples are now read from the gzipped files, and the Higgs
panel keeps only the pre-decay copy of each event (`|status| = 62`): the file holds ~7 copies of
the resonance per event, so counting all rows would over-state the Higgs rate by that factor.
The number of candidates printed in each panel title is the number of physical parents actually
used (B 1,509,528 / K 1,122,895 / Higgs 200,000).

## What each panel shows

* x = theta, the angle of the parent with respect to the beam axis, `atan(pT/|pz|)`,
  logarithmic from 1e-5 to 1 rad.
* y = p, the parent momentum, logarithmic from 1 to 1e4 GeV.
* colour = dsigma per 2-D bin, in **pb/bin**, logarithmic colour scale.
* 20 bins per decade on both axes: 100 theta bins and 80 momentum bins, fixed edges
  `np.logspace(-5, 0, 101)` and `np.logspace(0, 4, 81)`.  This is exactly the
  binning of the reference figure.
* cyclic `hsv` colour map; bins with no candidate are white.  Dsigma is per 2-D bin,
  not per unit area (the colour bar is labelled `pb/bin`).
* dashed diagonal line: p_T = p sin(theta) = m_X, where **m_X is the mass of the
  parent species**.  It marks the characteristic transverse-momentum scale of that
  parent, exactly as the reference does with p_T ~ m_B.
* vertical dotted lines: the **LHCb downstream** angular window 2 < eta_S < 5, i.e.
  theta(eta) = 2 atan(exp(-eta)):

      theta(eta=2) = 0.2690360 rad      (left line, labelled eta = 2)
      theta(eta=5) = 0.0134757 rad      (right line, labelled eta = 5)
      the label between them reads "LHCb downstream 2 < eta < 5"

  The brief quotes 0.26894 and 0.013544 rad; those are rounded/approximate values.
  The exact values of 2 atan(exp(-eta)) are the ones above (0.269036 and 0.0134757);
  the difference is below 0.5% in theta and is not visible at this axis scale.
* title (inside, top right, like the reference): species, **13 TeV**, `[pb/bin]`,
  the generator version (**Pythia 8.316**) and the number of candidates in the panel.

### Reference figure and the differences

The style follows **FORESEE** (F. Kling, J. Trojanowski, arXiv:2105.07077), Fig. 1,
right panel: *"B^0 at 14 TeV LHC [pb/bin], Pythia 8"* — same axes, same 20 bins per
decade, same `hsv` cyclic colour map, same dashed p_T = m_B line and dotted FASER /
FASER 2 acceptance lines.

**The reference is 14 TeV with FASER / FASER 2.  Ours is 13 TeV with LHCb downstream.**
Nothing here is a 14 TeV result.  The FASER windows (R/Delta = 10 cm / 480 m and
1 m / 480 m theta = 2.08e-4 and 2.08e-3 rad) are replaced by the LHCb downstream
2 < eta < 5 window above.

The reference spectra are for the forward hemisphere only (pz > 0).  Here the two
beam directions are folded together with `theta = atan(pT/|pz|)` (pz < 0 for 50% of
the b and Higgs samples; the kaon sample has pz > 0 only), so both hemispheres
contribute to one panel.  The normalisation below always uses the total pp cross
section and **all** candidates, so nothing is double counted: the plotted quantity is
the true dsigma/bins of the parent species in the LHCb-downstream angular range.

## Inputs and normalisation

| group | file | n_gen | sigma_ref | role |
|---|---|---|---|---|
| B | work/magnus/samples/bbar_heavy.txt | 800,000 | 5.0e8 pb (500 microbarn) | pp -> b bbar parents |
| K | work/magnus/samples/minbias_light.txt | 200,000 | 7.95e10 pb (79.5 mb) | inelastic pp (SoftQCD) |
| H | work/magnus/samples/higgs.txt | 200,000 | 55.4527 pb | SM Higgs (13 TeV production sum) |

`n_gen` and `sigma_ref` are read from `work/magnus/samples/normalisation.json`
(n_gen is the number of generated events, i.e. max event id + 1, not the number of
rows).  The master formula is the usual Monte-Carlo one:

    dsigma_bin [pb/bin] = sigma_ref * N_bin / n_gen

    sigma_expected [pb] = sigma_ref * N_candidates / n_gen
    sum over all bins    = dsigma_bin summed over the 100 x 80 bins

`N` counts **charge-combined** candidates of one species (B+ and B- together,
B0 and B0bar, Bs and Bsbar, K+ and K-, K0L and K0Lbar).  `N_candidates` is the number
inside the plotted window (1e-5 <= theta <= 1 rad, 1 <= p <= 1e4 GeV), which is
exactly the total content of the 100 x 80 histogram.

GeV, because the kaon sample already has theta <= 0.439 rad.

## What is included, what is excluded

* Charge-conjugate pairs are combined into one species (see the table above).
* **B_c (541, -541) is present in bbar_heavy.txt (1,107 rows) but is not used**: it is
  not an LLP parent in this analysis.  It is neither plotted nor counted in any
  closure number.
* **B baryons are absent.**  About 25% of b quarks hadronise to b baryons (Lambda_b,
  Sigma_b, ...), which are not scalar parents here; the file contains only B+, B0, Bs,
  Bc mesons.  The 1,055,619 rows correspond to 704,535 of the 800,000 generated
  events (88%), i.e. 1.32 B-meson rows per generated event.
* **The b sample has no eta cut** — it is the regenerated full-rapidity sample
  (`bbar_heavy.txt`, not the older `bbar_heavy_etacut.txt` with 1.5 < eta_B < 5.5).
* **The kaon sample is forward-only.**  minbias_light.txt contains K+/K- and K0L/K0Lbar
  with pz > 0 only (pz < 0 fraction is 0.0) and was generated with a 1.5 < eta < 5.5
  window (verified: eta range exactly [1.500, 5.500]).  The kaon panels therefore have
  data only for theta in [0.00817, 0.439] rad, with the LHCb window lines inside that
  range.  This does not bias the forward yield: with n_gen = 200,000 and
  sigma_inel = 79.5 mb, sigma_ref*N/n_gen is the average forward-kaon cross section
  per inelastic event, which is what the plot shows.
* **The Higgs sample holds several copies of the same Higgs per event** (1,235,376
  rows, 199,105 distinct events; the copies differ only in subprocess bookkeeping).
  **Only the first row per event id is kept**, giving 199,105 candidates from the
  200,000 generated events.  The subprocess codes 901-909 are not PDG codes.

## Sanity checks (printed by the script)

Hand check, first B+ row of bbar_heavy.txt:

    px = -3.2184751   py = -1.6738410   pz = 64.3215930   E = 64.6397570 GeV
    p = sqrt(px^2+py^2+pz^2)                          = 64.4238128 GeV
    sqrt(p^2 + m_B+^2),  m_B+ = 5.27934                = 64.6397639 GeV  (E_file - this = -6.9e-6 GeV)
    E^2 - p^2 = 27.87053 GeV^2      versus   m_B+^2 = 27.87143 GeV^2

A B+ with pz < 0 (event 5): px = 2.879739, py = -0.647971, pz = -2.784536,
E = 6.658595 GeV -> pT = 2.951739, p = 4.057882, theta = atan(pT/|pz|) = 0.814538 rad,
inside (0, pi/2).  pz < 0 occurs for 49.98% of the B rows and 50.16% of the Higgs rows;
using |pz| therefore folds the two hemispheres as intended.

Kinematic coverage of the samples (all rows; Higgs: first row per event):

    bbar_heavy     p in [0.071, 5062] GeV   theta in [2.2e-5, 1.571] rad   eta(|pz|) in [4e-7, 11.4]
    minbias_light  p in [0.017, 743] GeV    theta in [0.00817, 0.439] rad  eta in [1.500, 5.500]
    higgs          p in [0.821, 4542] GeV   theta in [4.96e-3, 1.571] rad eta(|pz|) in [3e-5, 6.0]

Invariant-mass consistency, sqrt(E^2-p^2): the B and K medians reproduce the nominal
masses (e.g. B+ median 5.279250, 0.1-99.9% [5.260, 5.298] GeV).  The small spread is a
storage-precision effect: E and the momentum components are written with 8 significant
digits, and at p ~ 3-5 TeV the physical difference E - p is only ~m^2/(2p) ~ 0.003 GeV,
comparable to the rounding of E, so the reconstructed mass there is good to ~0.08 GeV
only.  At low momentum the mass is exact.

**Observation — Higgs mass:** the generated Higgs mass is not a delta function: it
spans 125.05-125.45 GeV (1-99%: 125.200-125.300 GeV, median 125.25 GeV), i.e. the
generator sampled it over a finite range.  This is genuine in the file (it is far
larger than the storage rounding) but it has no effect on the (theta, p) spectra
plotted here.
