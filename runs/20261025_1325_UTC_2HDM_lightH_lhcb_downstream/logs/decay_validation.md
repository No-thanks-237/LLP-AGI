### 3.2 The 2 GeV hadron/parton matching

The author code switches description with **strict** inequalities:
π π / K K / 4π are floored for mH > 2; s sbar / g g are zero for mH < 2; and the
4π coefficient C = 5.1e-9 is tuned so that the two descriptions give the same
total width at 2 GeV (paper: "Decays to hadrons and quarks/gluons are connected
at m_H = 2 GeV"). Consequences:

| tanb | Gamma_tot(2−ε) | Gamma_tot(2.0) | Gamma_tot(2+ε) | at / below |
|---|---|---|---|---|
| 1 | 9.4094e-08 | 1.7420e-07 | 9.4556e-08 | **1.851** |
| 5 | 3.0727e-12 | 4.3809e-12 | 3.0806e-12 | **1.426** |
| 10 | 4.1542e-13 | 4.3561e-13 | 4.1566e-13 | **1.049** |
| 100 | 3.9432e-15 | 3.9438e-15 | 3.9444e-15 | 1.0002 |

* The total width is continuous across 2 GeV to 0.05–0.5 % (tanb ≥ 5) because of
  the tuned C; the *individual* channel widths jump abruptly (BR(ππ) 0.12 → 0,
  BR(ss) and BR(gg) appear).
* **At exactly mH = 2.0 both descriptions are evaluated**, so the program
  double counts there: Gamma_tot is 4.9 % too large at tanb = 10 and 85 % too
  large at tanb = 1 (negligible for tanb ≥ 100). Keep the node out of
  interpolation (see section 8).

### 3.3 Absence of b bbar

The author CP-even-H module has **no H → b bbar partial width at all**:
`DecayWidth_HTotal()` sums only γγ, ee, μμ, ττ, ππ, KK, 4π, cc, ss, gg
(partonic channels: c cbar, s sbar, g g; the b bbar channel was never implemented
for the CP-even H). This is why the physics scan is restricted to mH ≤ 10 GeV.
It is also harmless in the scanned range: the perturbative threshold used by the
authors for b bbar (2 m_B = 10.558 GeV, or 2 m_b = 8.36 GeV partonic) is above
10 GeV, so no open H → b bbar rate is missing. Above ~10.5 GeV the program would
underestimate the total width → do not use it beyond 10 GeV.

### 3.4 Physics content of the width (what is and is not in it)

* Included: γγ (quark loops + W loop + charged-Higgs loop through
  `gHCC = -(2 m_H±^2 - m_H^2) cos(β-α)/v`; **H→γγ is kept in the total width**
  even though its LHCb response is zero), e e, μ μ, τ τ, π π, K K, 4π
  (dispersion-relation form factors Θ, Γ, Δ from the author data base),
  c cbar (threshold 2 m_D), s sbar, g g (α_s from the author's α_s table,
  valid 1.2–246 GeV).
* Not in the model at these masses: H → h h / H → A A / H → H+ H− are all
  kinematically closed for m_H ≤ 10 GeV with m_h=125, m_A=m_H±=600; b bbar is
  not implemented (section 3.3) and is closed below 10 GeV anyway. ηη, ρρ, …
  are absorbed in the effective 4π coefficient C.
* γγ uses α_em = 1/137 (author choice, and the choice behind the paper figure and
  the FORESEE tables). Using a running α_em(m_H) instead would raise Γ_γγ by
  (137/α_em^-1)^2 (≈ +2 % at m_H ~ 1 GeV, +14.6 % if α_em = 1/128), which matters
  only where γγ dominates (large tanb). **Flagged as a convention, not changed**
  — the task fixes the author program as the width model.

## 6. Prefactor / normalisation cross-check against the paper formulae

DESIGN.md warns not to substitute another width model, so the code formulae were
checked algebraically against the paper:
* Paper App. A defines `A_{1/2} = [τ+(τ−1)f]/τ²`, `A_1 = −½[2τ²+3τ+3(2τ−1)f]/τ²`,
  `A_0 = −½(τ−f)/τ²` with `τ = m_φ²/(4m²)` — **identical** to the code's
  `AQ12H/AQ1H/AQ0H` (the code comment "there is no factor 2 here" refers to the
  paper's footnote that its normalisation differs from Djouadi's by 1/2).
* γγ: paper `Γ = G_F α²m³/(32√2π³)|ξ^γ|²` with `ξ^γ = Σ NcQ²ξA_{1/2} + ξ^V A_1`;
  using `G_F = 1/(√2v²)` this is `α²m³/(64π³v²)|ξ^γ|²`, **exactly** the code's
  `(1/137)²m³/(64π³v²)|xiHgaga_q + xiHgaga_w + xiHgaga_C|²`. A hand transcription
  gives 4.8972e-17 GeV at mH=0.1, tanb=10, identical to the executable.
* gg: paper `Γ = G_F α_s²m³/(36√2π³)|ξ^g|²` with `ξ^g = Σ(3/2)ξA_{1/2}`, i.e.
  `α_s²m³/(72π³v²)·(9/4)|ΣξA_{1/2}|² = α_s²m³/(32π³v²)|ΣξA_{1/2}|²`, **exactly**
  the code's `alphasQ²m³/(32π³v²)|xig|²` with `xig = (3/2)Σξ·AQ12H`.
  (The apparent 9/4 and 1/4 factors disappear once the ξ^g and ξ^γ normalisations
  are inserted: no discrepancy — this resolves the point raised in the planning
  report.)
* Small known differences, quantified, not changed (author program is authoritative):
  the code's γγ amplitude sums quarks + W + H± but omits the charged-lepton loop
  that appears in the paper's ξ^γ sum; a transcription of the formula shows this
  changes Γ_γγ by **−0.27 % at tanb = 10** and by < 1e-4 at tanb ≥ 100 (irrelevant
  for the LHCb downstream scan, which is dominated by tanb ≥ 10).
  The code also uses m_W = 80.4 and m_Z = 91.187 inside Γ_γγ while Parameters.h has
  80.390/91.190 — a < 0.01 % effect.

## 8. Caveats and recommendations for the scan (please read)

1. **mH = 2.0 GeV node**: the author program double counts (section 3.2):
   Γ_tot is +4.9 % (tanb=10), +43 % (tanb=5), +85 % (tanb=1) too large.
   The mass grid contains exactly 2.00000. **Recommendation**: drop that node from
   the tanb scan, or interpolate Γ across it from the neighbouring grid nodes
   1.81693 and 2.07163 GeV (the total width is continuous to <0.5 % there). The
   CSV flags it, and `decay_widths.py` documents it; the wrapper deliberately
   returns the program value unchanged. **Interfaces provided both ways**:
   `work/common/widths_img_13cols.txt` (67 masses, includes mH=2.0) and
   `work/common/widths_img_13cols_no2GeV.txt` (66 masses = `work/common/scan_mass_grid.txt`,
   2640 rows, mH=2.0 dropped — recommended for the scan); the matching point lists are
   `work/common/scan_points_tanb40{,_no2GeV}.txt`.
2. **hbar*c**: the authors' FORESEE tables use 2.0e-16 GeV m; the paper/prompt
   convention is 1.973269804e-16 (DESIGN.md section 0). We use the DESIGN value
   for all outputs (and provide the 2.0e-16 column in the CSV for cross-checks).
3. **BR sum**: the printed 11-digit widths give BR sums within 8.6e-11 of 1.
   If an exact sum is needed, renormalise by Σ BR (a 1e-10-level correction).
4. **α_em = 1/137** in Γ_γγ (author choice; see section 3.4). Only relevant where
   γγ dominates (large tanb, low mass).
5. Below the e e threshold / at very small masses Γ_tot is extremely small
   (4.6e-27 GeV at mH=0.021, tanb=5) and c*tau ~ 4e10 m; this is far outside the
   detector; no numerical problem was found down to mH = 0.021.
6. No physics edits were made. If the Lead wants a different γγ α_em or a bb
   channel, that is a model change and must be decided explicitly.
